| Variant | Routing | Memory | RAG | Purpose |
|---|---|---|---|---|
| Baseline | | | | fixed model, nothing else |
| Model A | x | | | does routing alone pick better models? |
| Model B | | x | | does memory alone give continuity? |
| Model C | | | x | does retrieval alone cut hallucination? |

Everything runs locally and free on Ollama. Cloud APIs (OpenAI, Anthropic, Gemini) are a config switch.

## Quick start

```bash
bash setup.sh                    # venv, deps, ollama models, train, index, tests
source .venv/bin/activate
streamlit run app.py             # interactive demo with the decision inspector
python scripts/run_ablation.py   # full ablation, writes results/
```

No Ollama? Everything still runs with the deterministic mock model:

```bash
ASSISTANT_PROVIDER=mock ASSISTANT_EMBEDDER=tfidf streamlit run app.py
python scripts/run_ablation.py --provider mock --embedder tfidf
```

## How it works

```
query -> Intent Classifier -> Router (scoring fn) -> Model pool -> answer
                 ^                                      ^
           Model A                     memory recall (B) + retrieved passages (C)
```

**Intent classifier** (`assistant/intent.py`): TF-IDF word 1-2 grams + char 3-5 grams, calibrated Linear SVM. Five intents: coding, writing, search, reasoning, multimodal. Dataset: `data/intents.csv`, 1,350 queries (450 hand-written seeds x 3 paraphrases), generated by `scripts/make_intent_dataset.py`.

**Router** (`assistant/router.py`):

```
score(model, intent) = w_a * accuracy[model][intent] + w_c * (1 - cost[model]) + w_l * (1 - latency[model])
```

Weights default to 0.6 / 0.2 / 0.2 and are user-adjustable in the UI. The full per-model breakdown is returned with every decision. `routing_gain()` measures how much the routed choice beats each fixed model on the same queries.

**Memory** (`assistant/memory.py`): SQLite. Three tiers: raw turns per session, one summary per session, and long-term facts extracted from first-person statements by a deterministic rule set. Recall is cosine top-k over embeddings, injected into the system prompt.

**RAG** (`assistant/rag.py`): documents in `data/corpus/` are chunked (120 words, 30 overlap), embedded, and retrieved by cosine similarity. Passages are numbered so the model cites `[1]`, `[2]`.

**Pipeline** (`assistant/pipeline.py`): `Assistant(routing=, memory=, rag=)`. The three booleans are the ablation.

## Benchmarks (`scripts/run_ablation.py`)

| Benchmark | What it measures | Data |
|---|---|---|
| routing | intent accuracy on a group-aware held-out split, routing gain vs each fixed model | `data/intents.csv` |
| memory | 24 facts stated over 4 sessions, 30 recall questions asked in a fresh session | `data/eval/memory_bench.json` |
| rag | 36 questions about a fictional company (Helix Robotics) that no model can know without retrieval; reports accuracy, abstention, hallucination, citation rate | `data/corpus/`, `data/eval/rag_qa.json` |

Hallucination rate = answers that are neither correct nor an explicit "I don't know".

Outputs: `results/ablation.json` (every answer), `results/ablation.csv`, `results/ablation.png`, `results/routing_gain.png`, `results/intent_metrics.json`.

## On the intent accuracy number

The held-out split is done per seed query, so paraphrases of a test query never appear in training. That gives ~84% (honest). A plain random split puts paraphrases on both sides and reports ~100%. Both numbers are in `results/intent_metrics.json`. Report the grouped one.

## Per-task benchmark (`scripts/run_task_bench.py`)

Answers the question "does each kind of task go to the right model, and is the answer right?"

- 50 tasks, 10 per intent, each written three ways (direct, casual, verbose) = 150 prompts for routing.
- Every task is answered by every model in the pool (temperature 0) and graded automatically: code is executed against unit tests, reasoning answers must hit the exact number, factual answers must contain the fact, writing must satisfy explicit constraints (line counts, word limits, JSON keys), and image questions use generated test images (`scripts/make_task_images.py`).
- Reports intent accuracy per phrasing, the measured model x intent accuracy matrix, and routed accuracy against every fixed model, the hindsight-best model per intent and an any-model upper bound. It also re-routes using the measured accuracies instead of the priors.

```bash
python scripts/run_task_bench.py            # ~200 model calls, 20-40 min on an 8 GB Mac
```
Outputs `results/task_bench.json`, `results/task_bench_raw.jsonl` (every answer), `results/tb_*.png`.
